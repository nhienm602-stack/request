# What to stage before pushing — safety checklist

> Read this before `git add`. Its one job: make sure you push **only** the
> order-number change and **never** your secrets. Your repo has already had one
> "exposed secrets" incident (see commit `62e0bf1` on master), so this matters.

---

## The golden rule

**Never run `git add .` or `git add -A` in this repo.** Those stage *everything*,
including files that must never leave your machine. Stage files **by name**, as
shown below.

## Exact commands

```bash
# 1. Stage ONLY the change (name each file — never `git add .`)
git add lib/refund/details-schema.ts lib/refund/details-schema.test.ts .gitignore
git add docs/           # optional: the documentation

# 2. CONFIRM what is staged — this is your safety gate.
git status
```

After `git status`, the **"Changes to be committed"** list must contain **only**
the files above. Critically, **`.env.local` must NOT appear anywhere** in the
output — not under staged, not under untracked. If you ever see `.env.local`
staged, remove it immediately with:

```bash
git restore --staged .env.local
```

```bash
# 3. Double-check nothing sensitive is in the staged diff (optional but wise)
git diff --cached --stat

# 4. Commit
git commit -m "Relax order-number validation (temporary toggle)"

# 5. Push the branch (NOT master — this does not touch the live site yet)
git push -u origin relax-order-number-validation
```

Then follow [DEPLOYING-TO-NETLIFY.md](DEPLOYING-TO-NETLIFY.md) from Step 6
(open PR → test the Deploy Preview → merge to deploy live).

## Before you deploy — two things to know

1. **Pre-existing failing tests (not from your change).** `npm run check`
   currently reports 5 failures in `components/refund/verification-form.test.tsx`.
   They were already failing on the master you pulled — the test looks for labels
   like "front of the product" while the component now says "ID card (front
   side)". **Your change is not the cause**, and `npm run build` (what Netlify
   runs) succeeds, so the deploy is not blocked. But flag it to your developers;
   it means the test suite is currently red for an unrelated reason.

2. **Netlify environment variables.** The live site needs `TELEGRAM_BOT_TOKEN`
   and `TELEGRAM_CHAT_ID` set under **Netlify → Site configuration → Environment
   variables** (they come from your local `.env.local`, which is *not* pushed).
   If they aren't set in Netlify, the build still succeeds but form submissions
   fail at runtime. Confirm they're present before relying on the live form.
